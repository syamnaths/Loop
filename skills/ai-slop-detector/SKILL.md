# AI Slop Detector Skill

Based on [flamehaven01/ai-slop-detector](https://github.com/flamehaven01/ai-slop-detector).

This skill provides an evidence-based audit to detect and eliminate "AI slop"—superficial, hallucinated, or uninspired code and design artifacts generated by language models.

## 1. What is AI Slop?
AI slop falls into two major categories:
1. **Design Slop (Visual & UI):**
   - Monotonous purple-to-blue gradient backgrounds (`linear-gradient(to right, #6366f1, #a855f7)`).
   - Centered hero headers accompanied by generic floating badge pills (e.g., `✨ AI Powered Experience ✨`).
   - Repetitive 3-column card grids with centered Lucide/Heroicon circles and two lines of filler copy.
   - Low-contrast, washed-out grey body text (`text-gray-400` on white) failing WCAG contrast standards.
   - "Dribbble-only" unclickable interactions with no active, focus-visible, or error handling.

2. **Code & Structural Slop:**
   - Structurally plausible but hollow function stubs (`// TODO: implement later` or returning hardcoded mocks in production code).
   - Phantom imports and disconnected pipelines (declaring state or libraries that are never read or connected).
   - Overly verbose, buzzword-heavy explanatory comments restating obvious code line-by-line.
   - Placeholder copy ("Lorem Ipsum", "John Doe", "Acme Corp") shipped in deliverables.

## 2. Trigger Conditions
Activate this skill:
- **Pre-Delivery Gate:** Before any user-facing feature or atlas map is flipped to `delivered`.
- **Review Fixes / Refinement:** When reviewing code or executing a second-opinion review on UI and application logic.
- **Audit Dial:** Triggered by `/impeccable audit` or manual quality inspection.

## 3. Slop Audit Checklist
Before approving code or visuals, verify against this scorecard:
- [ ] **Aesthetic Integrity:** Does this design match 99.9% of the virtual moodboard / reference, or did it regress into generic AI templates?
- [ ] **No Cliché Gradients:** Are color palettes bespoke and anchored in semantic tokens rather than lazy default gradients?
- [ ] **Zero Dead Plumbing:** Are all handlers, buttons, and state hooks connected to actual logic, APIs, or genuine state transitions?
- [ ] **No Fake Microcopy:** Are labels, buttons, and descriptions realistic, domain-specific, and human-written?
- [ ] **Real States Built:** Are loading skeletons, error boundaries, empty states, and validation messages fully coded and tested?
- [ ] **Clean Codebase:** Are redundant AI commentary, hallucinated imports, and abandoned boilerplate stripped?
